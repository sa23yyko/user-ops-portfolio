01PROJECT BRIEF

THE PROJECT / 项目定义

不是再做一款英语产品，
而是让学习更容易继续。

STAY English 是面向语言学习产品新用户的分层学习陪伴机制：在既有学习内容上，判断用户是谁、此刻需要什么，再给出更容易执行的下一步。

THE QUESTION ↘

如何识别早期学习阻力，并在合适时间，为不同用户匹配任务、提醒、反馈与中断恢复路径？

A / BACKGROUND

有学习需求，
不等于能够持续。

注册、首次学习、次日回访和习惯形成是不同关口；同一条“回来学习”的提醒无法解决所有阻力。

B / DELIVERABLE

把运营想法写成
可执行的规则。

从访谈与模拟 SQL 分析出发，交付用户分层、STAY Engine 规则、五个关键页面要求和 A/B 验证框架。

C / SCOPE

个人独立
模拟项目。

方案处于 PRD V1.0 设计阶段；访谈与行为数据均为模拟资料，尚未在真实产品中上线。

06VALIDATION

TEST BEFORE CLAIM / 验证框架

方案需要被测试，
不能被写成结果。

PRD 给出三组 A/B 实验，对应首学门槛、提醒相关性与中断恢复。只有真实随机分组并正确采集数据后，才有资格讨论效果。

E01

低门槛首日任务

假设：降低首次任务负担，可能帮助更多新用户完成第一轮学习。

A / CONTROL默认首次任务
B / TREATMENT10 分钟任务＋预计时间＋即时反馈
PRIMARY / 首日完成率、激活率　·　FOLLOW-UP / D1、D7
E02

分层提醒文案

假设：按需求分层匹配提醒文案与入口，可能提高触达相关性。

A / CONTROL所有用户统一提醒
B / TREATMENT按四类需求匹配提醒
PRIMARY / 提醒点击率、点击后开始学习率
E03

断签恢复

假设：温和的恢复路径，可能减少一次中断后的放弃。

A / CONTROL断签后重新计数
B / TREATMENT有限补签＋温和恢复文案
PRIMARY / 断签后 3 日回访率、再次学习率
BEFORE LAUNCH / 验证前提

01 / 随机分组
按真实基线、MDE 与功效估算样本量。

02 / 口径统一
明确曝光、点击、开始、完成与学习留存埋点。

03 / 护栏指标
检查退出率、提醒关闭率、负面反馈与异常短任务。
